# Magic SQD

Программа с графическим интерфейсом для установки приложений на
Android-магнитолы китайских авто — через ADB или через USB-флешку (для
моделей, где ADB недоступен). Все данные (марки/модели, инструкции,
скрипты установки, стандартные APK) лежат рядом с .exe в открытом виде и
легко редактируются без пересборки программы.

## Структура (то, что лежит рядом с .exe)

```
magic_sqd.exe
assets/
    icon.ico                  <- иконка окна и .exe
    splash.png                 <- картинка сплеш-скрина при запуске
tools/
    adb.exe                  <- положить сюда platform-tools (см. tools/README.txt)
    AdbWinApi.dll
    AdbWinUsbApi.dll
apk/
    yandex_navi.apk           <- любые общие APK, появятся как галочки в программе
    yandex_navi.json          <- (опц.) {"name": "...", "description": "..."}
cars/
    _shared/                  <- (опц.) общий .py код для install.py разных моделей
    Chery/
        Tiggo 7 Pro (MTCD)/
            instruction.html   <- инструкция по получению доступа к ADB / по USB-установке
            install.py         <- скрипт установки по ADB (контракт: функция run(ctx))
            files/             <- файлы/утилиты для install.py (ADB-режим)
            usb_install.py     <- (опц.) скрипт для режима "USB-флешка", контракт: run(ctx)
            usb_files/         <- (опц.) файлы, которые по умолчанию копируются на флешку
            stages.py          <- (опц.) многоэтапная установка (флешка + ADB + ручные шаги)
    Geely/
        Coolray (MTCA)/
            ...
    Demo/
        Test Model X1/         <- рабочий пример-шаблон, скопируйте для новой модели
```

Папки-марки, начинающиеся с `_` (например `_shared`), в списке марок не
показываются — это служебная зона.

## Добавление новой марки/модели

1. Скопируйте `cars/Demo/Test Model X1` в `cars/<Марка>/<Модель>`.
2. Отредактируйте `instruction.html` — впишите реальные шаги и скриншоты
   (просто `<img src="...">`, картинки кладите рядом, например в `images/`).
3. Отредактируйте `install.py` — используйте методы `ctx.*` (описаны в
   комментарии в начале файла): `ctx.install_apk`, `ctx.shell`, `ctx.push`,
   `ctx.reboot`, `ctx.install_selected_apks()` и т.д.
4. Специфичные для модели файлы (патченые APK, утилиты разлочки) кладите в
   `files/` рядом и берите через `ctx.file("имя_файла")`.
5. Перезапускать программу не обязательно — модель появится в списке при
   следующем запуске (при желании легко добавить кнопку "Обновить список").

## Контракт install.py

```python
def run(ctx):
    ctx.log("сообщение в лог программы")
    ctx.install_apk(ctx.file("special.apk"))   # файл из files/ этой модели
    ctx.install_selected_apks()                # то, что отмечено галочками в apk/
    ctx.shell("pm grant com.example.app ...")  # произвольная adb shell команда
    ctx.push(local_path, "/sdcard/...")
    ctx.reboot(wait=True)
```

Если что-то пошло не так — просто `raise Exception("текст ошибки")`,
программа покажет его пользователю и остановит установку. Полный список
доступных методов — в `app/install_context.py`.

## Установка через USB-флешку

Для моделей, где ADB недоступен (или неудобен), в программе есть кнопка
"Через USB-флешку...". Она открывает отдельное окно, где можно:

1. Выбрать флешку из списка (показываются только съёмные USB-накопители —
   системный и внутренние диски программа физически не даст выбрать).
2. Опционально отформатировать её (FAT32 — для флешек до ~32 ГБ, обычно
   именно это нужно магнитолам; exFAT — для больших флешек). Перед
   форматированием всегда требуется явное подтверждение с указанием буквы
   диска, метки и размера.
3. Скопировать нужные файлы на флешку.

По умолчанию (если у модели нет `usb_install.py`) копируются содержимое
папки `usb_files/` этой модели и все отмеченные галочками APK из общей
`apk/` — прямо в корень флешки. Этого достаточно в большинстве случаев,
писать код не нужно.

Если модели нужна нестандартная раскладка файлов на флешке (переименование,
подпапки, служебный конфиг для автообновления), создайте `usb_install.py`
рядом с `install.py`:

```python
def run(ctx):
    ctx.log("Готовлю флешку")
    ctx.copy_file(ctx.usb_file("app.apk"), "update/app.apk")
    ctx.copy_selected_apks("update/apps")
    ctx.write_text("update/install.cfg", "AUTO_INSTALL=1\n")
```

Полный список методов `ctx` для этого режима — в `app/usb_context.py`
(`copy_file`, `copy_dir`, `copy_selected_apks`, `write_text`, `usb_file`,
`file`, `log`).

## Многоэтапная установка (флешка + ADB + ручные шаги)

Некоторые магнитолы требуют установку в несколько шагов разного типа —
например: сначала записать файлы прошивки на флешку и обновить прошивку
через файловый менеджер магнитолы, потом (когда появится ADB) доустановить
приложения по ADB, а затем ещё раз записать APK на флешку и поставить его
вручную через файловый менеджер. Обычные `install.py`/`usb_install.py`
для этого не подходят — они устроены как один шаг одного типа.

Для таких моделей создайте рядом `stages.py` — тогда в программе появится
кнопка "Установка по этапам...", открывающая мастер: список этапов слева,
инструкция и лог справа, кнопка действия — своя для каждого типа этапа.

```python
def _usb_firmware(ctx):                 # ctx — как в usb_install.py (UsbContext)
    ctx.copy_dir(ctx.file("firmware"), "")

def _adb_install_apps(ctx):              # ctx — как в install.py (InstallContext)
    ctx.install_selected_apks()

STAGES = [
    {
        "type": "usb",                   # "usb" | "adb" | "manual"
        "title": "Флешка №1 — прошивка",
        "description": "Скопируйте файлы, извлеките флешку и вставьте в магнитолу.",
        "run": _usb_firmware,            # обязателен для "usb" и "adb"
    },
    {
        "type": "manual",                # шаг, который пользователь делает руками
        "title": "Обновление прошивки на магнитоле",
        "description": "Запустите обновление с флешки и дождитесь перезагрузки.",
        # для "manual" run не нужен — в мастере просто кнопка "Готово, далее"
    },
    {
        "type": "adb",
        "title": "Установка приложений по ADB",
        "run": _adb_install_apps,
    },
]
```

Вместо `description` можно указать `"instruction": "stage1.html"` — имя
html-файла рядом со `stages.py` (так же, как основной `instruction.html`),
если нужно оформление/скриншоты для конкретного этапа.

Пользователь сам переключается между этапами в списке (это не строгий
одношаговый визард) — удобно, если какой-то шаг нужно повторить, например
если флешка не заработала с первого раза. Полный рабочий пример — в
`cars/Demo/Test Model X1/stages.py`.

## Запуск из исходников (для разработки)

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python main.py
```

## Сборка .exe

```powershell
.\.venv\Scripts\pyinstaller magic_sqd.spec
```

Готовый `dist\magic_sqd.exe` скопируйте туда, где будут лежать
`cars\`, `apk\`, `tools\` и `assets\` — например на флешку или в рабочую папку
на ноутбуке. Сама программа кода не содержит "жёстко зашитых" моделей — всё
подхватывается из соседних папок.

## Иконка и сплеш-скрин

`assets\icon.ico` — иконка `.exe` (зашивается в файл при сборке через
`icon=` в `magic_sqd.spec`) и иконка окна во время работы программы.
`assets\splash.png` — картинка, которая на пару секунд показывается при
запуске, пока программа читает `cars\`/`apk\` и грузит `tkinterweb`. Если
`assets\splash.png` рядом с `.exe`/`main.py` нет — сплеш просто не
показывается, программа стартует как обычно.

Если понадобится заменить логотип — исходник лежит в
`assets\icon_source.png` (1024×1024). Пересобрать `icon.ico`/`icon.png`/
`splash.png` из него:

```powershell
.\.venv\Scripts\pip install Pillow
.\.venv\Scripts\python -c "from PIL import Image; im = Image.open('assets/icon_source.png').convert('RGBA'); im.save('assets/icon.ico', sizes=[(s,s) for s in (16,24,32,48,64,128,256)]); im.resize((256,256)).save('assets/icon.png'); im.resize((420,420)).save('assets/splash.png')"
```

## adb.exe

Программа сначала ищет `tools\adb.exe` рядом с собой, и только если его там
нет — использует `adb` из системного PATH. Проще всего один раз положить
папку `platform-tools` (adb.exe + пара .dll) в `tools\` и больше об этом не
думать.
