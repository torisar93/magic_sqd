Отдельная копия adb.exe/fastboot.exe/AdbWinApi.dll/AdbWinUsbApi.dll ТОЛЬКО
для Windows 7 (x86)-сборки (см. installer_win7_x86.iss) — НЕ используется
обычной x64/x86-сборкой (у той своя копия в tools\).

Причина: текущий tools\adb.exe (platform-tools 35.0.1, 2024) на настоящей
Windows 7 падает с "adb.exe — прекращена работа" (реальный случай,
проверено на живой машине) — тот же класс проблемы, что и с WebView2/
Python 3.9+: свежие официальные сборки Google/Microsoft постепенно
перестают запускаться на этой ОС, даже если PE-заголовок формально x86.

Здесь — platform-tools r29.0.6 (ноябрь 2019, https://dl.google.com/
android/repository/platform-tools_r29.0.6-windows.zip) — заведомо из эпохи,
когда Windows 7 ещё официально поддерживалась. Протокол ADB обратно
совместим — старый клиент adb.exe нормально ставит APK/выполняет shell-
команды на новых версиях Android на магнитоле, слать команды именно
СВЕЖИМ adb.exe не обязательно.

Если этот класс проблем повторится на реальной Windows-7-машине даже с
этой версией — взять ещё более старый platform-tools-релиз с той же
страницы архива (просто поменять номер версии r29.0.6 на более ранний
в URL выше — архив держит все исторические версии).
